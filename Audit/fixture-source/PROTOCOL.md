# FRONT-CORRECT-01 — retained-run predeclaration

Date: 8 October 2026. This is a reconstructed implementation after an interrupted attempt whose temporary bytes were unavailable. The earlier result reports guided recovery; this is not blind design or external preregistration. A new freeze precedes this retained execution. Original v0.4 evidence is unchanged.

Question: can finite recorded-support maintenance retain history, reject unsupported selected proofs, recover independent support, and separate correction from permission and revalidation? Scope: synthetic positive Horn proof graphs and disposable SCT dictionary snapshots, not an LLM, a deployed security boundary, or actual human deception.

## Fixed workload and policies
25 named templates in 16 key-required families × chain lengths 4,16,64 = 75 cases; three quiet cases ask nothing; others request q,z,safe, totaling 216 support decisions per arm. Source P supplies a challenged root; A and B supply optional conjunctive independent support. Historical USED edges remain relevant if the current graph removes a link. A different source version has a distinct witness ID. Cases have supplied trust/meaning/scope metadata, not inferred real-world trust. Expected support is in cases.json and not passed to the evaluated policy.

A: unchecked answer/proof reuse (deliberately unsafe control). B: blanket invalidation of recorded downstream entries, with basic whole-graph Horn closure separately for each requested invalidated conclusion. C: recorded-support reopening and demand checking, conjunctive parents, alternative proofs, successful-subproof memoization, no self-support through cycles. B is intentionally basic and does not share recomputations across queries; no comparison against optimized ATMS/incremental SAT is claimed.

Every arm uses the same explicit effect/seat/scope/expiry grant gate. Methods to the same denied effect stay denied. Requests produce tokens only; no external action is executed. Gate correctness is NOT attributed as an advantage of C. An unsupported lookup is UNRESOLVED, not a proof of negation. Intent is never inferred. Trace prefix is retained.

## Oracle, correction and controls
Separate oracle module computes least fixed points and validates returned proof IDs against only their declared current support. Same assistant authored all modules; code-path separation is not independent referee review.

A separate 96-case scratch-repair assay enumerates e,s,h∈{0,1}, lock∈{none,0,1}, grant∈{false,true}, candidate e∈{0,1}. Validator checks e+s+h≤1 and lock; oracle constructs an actual finite binary row and counts internal zeros. A changed candidate requires permission, is applied to scratch, and is committed with a new version only after validation; failed scratch changes roll back, with failure history retained. An unchanged valid state requires no mutation grant. No-return is not success. This models a dictionary transaction, not durable filesystem/crash repair.

Supplemental exact controls enumerate 5,040 SCT OR orders, 1,024 two-atom Horn systems / 2,048 queries against explicit valuation tables, and 525 prepaid operation-budget checks (75 cases × budgets 0,1,2,4,16,64,512). Budget counting prices index/node/rule/premise/root/basis increments; bytes have separate accounting. This is not a wall-time or memory limit. Partial proofs are not admitted.

Eight deliberately corrupted-output controls test history erasure, invented intent, stale support, hash-as-warrant, invented coverage, NO-type collapse, alternate-tool grant bypass, and unwanted quiet-task continuation. These are intentional negatives, not concealed clean-run errors.

## Measurement and stopping
One untimed warmup per case/arm, then five technical repeats with rotating arm order. Correctness counts use repetition zero; repetitions must agree semantically. Calls include fixture reads/parsing, policy work, and in-memory history serialization. Oracle and event-log serialization/write time are reported separately. Source indexes, reads/hashes, graph traversal, proof construction, provenance bytes and failures remain counted. Whole-run peak RSS is not per-arm memory or unique information. Timings are exploratory warm-cache Python microbenchmarks; no significance test, production claim, token result, or general complexity bound follows. Report all cases where C loses to B.

Freeze all source/protocol/fixture files before execution, refuse modification and existing result directories, retain failure receipts if anything fails. Normal and python -O executions must agree in substantive results. The real-model and Lean lanes remain unrun.
