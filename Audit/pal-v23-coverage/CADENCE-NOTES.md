# PAL v2.3 A13 cadence lane notes

This bounded Lean supplement formalizes finite relational cadence from PAL v2.3-M A13. It treats state transitions as supplied relations, not as verified scheduler observations.

`AdminClosure` is a reflexive, finite transitive closure over the supplied administrative relation. The `Macrostep` definition composes an administrative closure, one productive edge, and another administrative closure. A supplied projection remains equal over the administrative closure. A full macrostep preserves work only when its productive edge preserves work too; a separate theorem shows that a productive change to a supplied progress coordinate survives administrative stuttering.

For a supplied Nat rank, administrative equality plus strict productive-edge descent yields strict rank descent over every macrostep. `MacroRun` indexes a finite path by its exact macrostep count; induction proves that count is at most the initial rank. This is a finite bound conditional on those premises. It does not establish that a scheduler supplies a productive edge, fairness, infinite recurrence, or general liveness.

The countercases preserve the intended seams. Nat×Nat has an administrative edge that leaves one projection fixed while changing another coordinate used as rank. For every finite n, the identity administrative relation has an exact n-step MacroRun while the productive relation is empty; this is a finite witness only, not infinite recurrence or scheduler liveness. A separate Nat countercase preserves a constant work projection and makes every productive edge lower the identity rank, but an admin edge 0→1 replenishes that rank before a productive edge 1→0, so the composed macrostep 0→0 has no net strict descent. This demonstrates why administrative rank preservation is load-bearing. A Bool endpoint fixture has distinct consecutive values yet returns to its initial observed value; it illustrates sparse-endpoint ambiguity without modeling a real hidden worker or transition source.

All source-authored declarations are inventoried in `cadence-claims.json`: both inductive types, their four constructors, the macrostep definition, and the named theorems/countercases. Lean's `AdminClosure.rec` and `MacroRun.rec` are generated eliminators, not separately authored definitions or claim declarations. The `#check @` and `#print axioms` lists match the 16 ledger rows in order. Both targeted modules build; every inventoried declaration is axiom-free. A separate anonymous fixture typechecks the arbitrary progress codomain.
