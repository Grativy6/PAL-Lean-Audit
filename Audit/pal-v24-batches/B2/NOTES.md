# B2 — Source-path replay realization

B2 implements a small finite source-path model for the candidate M-SOURCE-PATH route through SC-22.3 / D41 / O64 / T74. It is development evidence only. Candidate DOCX SHA-256 values remain `PENDING_CONTROLLER_BIND_AFTER_FREEZE`; this directory is not a final batch receipt and the batch runner is intentionally not run before the controller freezes and binds the candidate documents.

`CheckResult` represents `yes`, `no(reason)`, and `unknown(reason)` as distinct constructors. `checkedReplay` returns the complete list of per-record and coverage results unchanged, alongside a summary and optional final modeled state. The summary selects the first non-yes result in audit order; if it is unknown, that unknown constructor and reason are returned, while later failures or unknowns remain visible in the full audit. Admission is fail-closed: only an all-yes audit yields status yes and an output. An unknown result is never rewritten as no, pass, false, or zero.

The checks are separate. `contentCheck` tests a stored successor against the declared natural-number addition rule. `associationCheck` checks supplied source ID, input channel, adapter version, and explicit event-code mapping. `applicabilityCheck` checks the supplied current task and version and that the adapter's canonical channel matches the context. `orderCheck` checks predecessor linkage, and `coverageCheck` checks exact expected event IDs and order. These are checks against declared caller-supplied values; none authenticates that an ID, channel, source, event, or result came from an external origin.

`history_yes_chain` derives `transitionChain` when every recursive per-record history check is yes; `admitted_fullAudit_implies_transitionChain` specializes this bridge to the initial state of the context and an all-yes `fullAudit`. Thus `content_chain_replay` remains a conditional theorem, but a successful modeled admission now supplies its required transition-link and content-check premise. `checkedReplay_success_matches_runKnown` further proves that any yes/some output returned by this checker equals the declared finite natural-number transition run. These implications establish consistency only inside the declared model. They do not establish source authenticity, external task applicability, or that an external history is complete. The separate fixture `consistent_content_wrong_event_binding` witnesses why content consistency alone does not prove association.

The positive fixture uses input channel 11 mapped by an explicit adapter to canonical channel 19, version 4, and event codes 5/6 mapped to event IDs 50/60. The tested history carries state 0 through 2 to 5. Negative fixtures cover unchanged-channel source replacement, stale version, reordering, missing events, altered value, a content-consistent wrong event binding, task mismatch, and an unknown signature-check result that blocks replay while preserving its reason and the entire audit.

All 49 explicit declarations in `Experiments.Pal24SourcePath.lean` are inventoried in `claims.json`. The companion module has one fully qualified `#check @...` and one `#print axioms ...` for each declaration in matching order. Targeted development builds passed for `Experiments.Pal24SourcePath` and `Experiments.Pal24SourcePathAxioms`; the printed dependencies are only Lean's ordinary `propext`, `Classical.choice`, and `Quot.sound` where required. No user-declared axioms, proof holes, `native_decide`, `unsafe`, or Omega identifier were added.

The source inputs include repository snapshots of PAL v2.3 M, Spine, and T extracts plus `source-verification.json`, each hashed as currently stored. The three candidate DOCX paths are listed with pending hashes because the candidate is not frozen. Those pending fields must be replaced by the controller with exact post-freeze hashes before a receipt run. No source DOCX or original corpus file was edited.

**Authority and interpretation ceiling:** this is a typed, finite mathematical realization of selected source-path distinctions. It does not close O64 or O04/O25/D-FIRST-OCCURRENCE; prove cryptographic authenticity, provenance truth, witness standing, consent, applicability beyond the declared check, replay authority, durable storage, or adequacy for a real external task; nor does it amend/adopt PAL v2.4.
